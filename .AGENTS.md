# ThothBlueprint Agent Guide

This file is the repository-level operating guide for coding agents. Read it before changing code. Load the relevant skill from `.agents/skills/` when a task touches one of the areas listed below.

## Project Snapshot

- ThothBlueprint is a browser-based, offline-first database diagram editor.
- The application is React 18 + TypeScript + Vite.
- Zustand owns editor state, Dexie owns browser-local IndexedDB persistence, and React Flow renders the diagram.
- Tailwind CSS and the existing shadcn/Radix-style primitives provide the UI layer.
- Core editing must continue to work without a server or network connection.

## Before Editing

1. Inspect the existing implementation and nearby patterns before introducing an abstraction.
2. Read the applicable skill in `.agents/skills/` for editor, persistence, import/export, AI, code generation, or PWA work.
3. Check `git status --short`. Do not revert or overwrite changes that are not part of the current task.
4. Keep changes focused. Do not reformat unrelated files or modify generated `dist/` output by hand.
5. Prefer existing names, types, utilities, components, and store actions over parallel implementations.

## Source Layout

- `src/App.tsx`: React Router routes. Keep routes centralized here.
- `src/pages/`: route-level views; the main page is `src/pages/Index.tsx`.
- `src/components/`: editor, dialogs, layout, and UI components.
- `src/components/ui/`: shadcn/Radix-style primitives. Treat these as generated/shared primitives; do not edit them directly unless the task explicitly requires it.
- `src/store/store.ts`: Zustand state orchestration and diagram mutations.
- `src/lib/`: persistence, domain types, parsers, import/export, AI, layout, and code generation.
- `src/hooks/`: reusable React hooks.
- `src/workers/`: browser workers, including SQLite parsing.
- `src/globals.css`: global CSS variables and shared styles.
- `public/`: static and PWA assets.
- `docs/`: project documentation.

Use the `@/` alias for source imports. Follow the surrounding file's quote and formatting style; there is no Prettier configuration. TypeScript is strict, so keep types explicit and do not use `any` without a concrete boundary reason.

## Required Invariants

- Table nodes are `AppNode`; notes and zones are separate node types. Keep their data shapes aligned with `src/lib/types.ts`.
- Table and column IDs are persisted identifiers. Do not change ID formats casually.
- Relationship edges reference source/target table IDs and column handles. Composite relationships carry `sourceColumns`, `targetColumns`, and `isComposite` metadata.
- React Flow changes should go through the appropriate Zustand action so they reach the persisted diagram, not only an in-memory React Flow instance.
- Respect diagram and zone locking for every mutation path, including dialogs, keyboard actions, paste, and AI operations.
- Keep visible UI connected to the main page/editor flow. A component that is not rendered from the active flow is not a delivered feature.

## Persistence Rules

- IndexedDB is implemented in `src/lib/db.ts` with Dexie. Any persisted shape or index change requires a new Dexie version and an upgrade path where needed.
- Preserve the store's debounced position/full-save behavior and transaction boundaries. Do not add ad hoc writes that race the store subscription.
- Review trash, permanent deletion, restore, checkpoints, and backup behavior when changing diagram data.
- Backups include diagrams, selected diagram state, and AI chat sessions; they do not automatically include every local store such as checkpoints or settings.
- Treat dates loaded from JSON as dates before using them in persisted records.

## AI Rules

- Keep the pipeline intact: provider response -> parse -> Zod schema validation -> simulation -> atomic Zustand commit.
- Do not apply raw model output directly to the store and do not bypass `src/lib/ai/simulateAiPatch.ts`.
- Never log API keys, decrypted credentials, or full diagram payloads unnecessarily.
- Preserve the distinction between cloud providers and local Ollama/LM Studio providers. Cloud requests can contain schema data.
- Handle streamed, malformed, truncated, retried, and rejected responses without leaving partial diagram mutations.

## Import, Export, and Code Generation

- Select the parser/exporter for the diagram dialect: MySQL, PostgreSQL, SQLite, DBML, JSON, Mermaid, or framework migration generators.
- Preserve IDs, positions, colors, locks, and relationship metadata where a round trip promises to preserve them.
- SQLite DDL parsing runs in `src/workers/sqlite-ddl.worker.ts`; do not move worker-only dependencies into the UI path without a reason.
- Generated SQL and migrations are candidate artifacts. Review dialect-specific syntax, identifier quoting, foreign keys, composite keys, and destructive operations manually.

## UI and Runtime Rules

- Prefer existing shadcn/Radix primitives and `lucide-react` icons. Use Tailwind classes and existing CSS variables before adding new global CSS.
- Preserve responsive behavior, keyboard shortcuts, selection semantics, and locked-state affordances.
- Preserve PWA behavior in `vite.config.ts`, including service-worker updates, offline fallback, and cache limits.
- `package.json` is the version source. `vite.config.ts` injects `__APP_VERSION__` and `__GIT_HASH__` at build time.

## Validation Gate

Use pnpm and run these commands from the repository root:

```bash
pnpm run type-check
pnpm run lint
pnpm run build
```

`build` has a `prebuild` lifecycle hook that runs type-check and lint again, so the build output intentionally contains the full prebuild chain before `vite build`. The lint command is:

```bash
eslint . --ext ts,tsx --report-unused-disable-directives --max-warnings 5
```

There is currently no `test` script or configured test runner in `package.json`; do not claim tests passed or add instructions for `pnpm test` unless a test runner is added as part of the task. For behavior changes, perform a focused browser smoke test in addition to the static gate when practical.

Before reporting completion, inspect `git diff --check`, `git status --short`, and the final diff. Report commands that passed, failed, or were not run.

## Documentation Caveats

- `CONTRIBUTING.md` contains stale Jest/React Testing Library and Prettier instructions. The package scripts and `.github/copilot-instructions.md` are authoritative for the current toolchain.
- `components.json` points shadcn at `src/index.css`, but the active global stylesheet is `src/globals.css`. Follow the actual imports unless fixing the configuration is explicitly requested.
- Release notes may contain historical statements that predate current SQLite support. Do not use historical notes as an implementation contract.
- `docs/VERSIONING.md` uses an illustrative version in its example. Read the current version from `package.json`.
